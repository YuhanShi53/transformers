流形约束超连接 (Manifold-Constrained Hyper-Connections)

DeepSeek-V4 用 mHC 替代了传统的残差连接 y = x + f(x)。核心思想是维护 hc_mult=4 条并行残差流， 每个子层（Attention / FFN）通过可学习的 pre-combination 和 post-combination 矩阵，动态决定如何混合这些流。 组合矩阵通过 Sinkhorn 迭代约束为双随机矩阵（每行每列和为1），保证信息在流形上的均匀传播。

源码位置：model.py Block 类 (L647-700)，kernel.py hc_split_sinkhorn_kernel (L371-427) + wrapper (L430-438)

hc_pre — 预组合（4条流合为1）

将 4 条残差流加权合并为单一向量，送入子层（Attention 或 FFN）。权重由 Sinkhorn 核产生的 pre 向量控制。

def hc_pre(self, x, hc_fn, hc_scale, hc_base):
    # x: [b, s, hc, d] = [b, s, 4, 7168]  ← 4条残差流
    # hc_fn: [24, 28672]  (mix_hc=24, hc_dim=4×7168=28672)
    shape, dtype = x.size(), x.dtype
    x = x.flatten(2).float()       # [b, s, 28672] ← 4条流拼接
    rsqrt = torch.rsqrt(x.square().mean(-1, keepdim=True) + self.norm_eps)
                                    # [b, s, 1] ← RMSNorm 的归一化因子
    mixes = F.linear(x, hc_fn) * rsqrt
                                    # [b, s, 24] ← 线性投影 + 归一化
    pre, post, comb = hc_split_sinkhorn(mixes, hc_scale, hc_base,
                                         self.hc_mult, self.hc_sinkhorn_iters, self.hc_eps)
    # pre:  [b, s, 4]    ← sigmoid 门控
    # post: [b, s, 4]    ← 2×sigmoid 门控
    # comb: [b, s, 4, 4] ← Sinkhorn 双随机矩阵
    y = torch.sum(pre.unsqueeze(-1) * x.view(shape), dim=2)
    # pre.unsqueeze(-1): [b, s, 4, 1]
    # x.view(shape):     [b, s, 4, 7168]
    # 加权求和 dim=2:    [b, s, 7168] ← 4条流合为1
    return y.to(dtype), post, comb

hc_post — 后组合（子层输出分配回4条流）

子层（Attention/FFN）的输出是单一向量 [b, s, d]，hc_post 将其通过 post 门控分配到 4 条流， 并通过 comb 双随机矩阵混合残差：

def hc_post(self, x, residual, post, comb):
    # x:        [b, s, d]      = [b, s, 7168]     ← 子层输出
    # residual: [b, s, hc, d]  = [b, s, 4, 7168]  ← 原始4条流
    # post:     [b, s, hc]     = [b, s, 4]         ← 后门控
    # comb:     [b, s, hc, hc] = [b, s, 4, 4]      ← 双随机矩阵
    y = post.unsqueeze(-1) * x.unsqueeze(-2) \
      + torch.sum(comb.unsqueeze(-1) * residual.unsqueeze(-2), dim=2)
    # ── 第一项: 新信息注入 ──
    # post.unsqueeze(-1):         [b, s, 4, 1]
    # x.unsqueeze(-2):            [b, s, 1, 7168]
    # → broadcast乘:             [b, s, 4, 7168]  ← post[i]控制注入到流i的强度

    # ── 第二项: 残差流双随机混合 ──
    # comb.unsqueeze(-1):         [b, s, 4, 4, 1]  ← axes: [b, s, i_out, j_in, d]
    # residual.unsqueeze(-2):     [b, s, 1, 4, 7168]
    # → broadcast乘:             [b, s, 4, 4, 7168]
    # → sum(dim=2):              [b, s, 4, 7168]  ← 对 j_in 求和
    # 注意: unsqueeze(-2) 使 residual 的 hc 维度在 dim=3,
    # sum(dim=2) 对乘积的 i_out 维度求和 → 效果等价于矩阵乘 comb @ residual
    # 即 output[i] = Σⱼ comb[i,j] × residual[j]

    # 最终: y[i] = post[i]×f(x) + Σⱼ comb[i,j]×residual[j]
    # y: [b, s, 4, 7168] — 更新后的4条残差流
    return y.type_as(x)
mHC 的直觉： 传统残差 y = x + f(x) 只有"加"这一种组合方式。 mHC 的 4 条流 + 双随机矩阵实际上允许每层动态学习一个"排列+缩放"操作： output[i] = post[i]×f(x) + Σⱼ comb[i,j]×residual[j]。 由于 comb 是双随机矩阵（行列和为1），信息量守恒，不会出现某条流消失或膨胀。

Sinkhorn 核 — 生成双随机组合矩阵

hc_split_sinkhorn 将 24 维 mixes 向量拆分为 pre / post / comb 三部分，并将 comb 约束为双随机矩阵。 具体步骤：先对 comb 做 softmax（行归一化），再做列归一化，然后交替 行归一化→列归一化 × (sinkhorn_iters−1) = 19 次。 合计 1 次初始 softmax + 1 次列归一化 + 19 轮交替 = 20 轮归一化，对应 hc_sinkhorn_iters=20：

混合注意力 (Hybrid Attention Architecture)

DeepSeek-V4 的注意力机制从 V2/V3 的 MLA (Multi-head Latent Attention) 演进而来。 底层 Q/KV/O 路径仍保留了 MLA 的核心设计——低秩 Q 投影、单头联合 KV latent、分组低秩 O 投影—— 因此推理源码 model.py 中 Attention 类的注释仍然沿用 "MLA" 名称（L437）。 但在此基础上，DeepSeek-V4 引入了全新的混合压缩注意力架构， 通过不同压缩策略将 61 层分为两类：

  • HCA (Heavily Compressed Attention, ratio=128) — 128 个 token 压缩为 1 条 KV 记录，无 Indexer，全量访问压缩 KV
  • CSA (Compressed Sparse Attention, ratio=4) — 4 个 token 压缩为 1 条 KV 记录（带 overlap 窗口），通过学习型 Indexer 选择 top-k=1024 最相关的压缩 KV

所有层共享一个大小为 128 的滑动窗口，保证局部信息的无损传递。 这种 HCA+CSA 交替的混合架构，使得 DeepSeek-V4 在 1M 上下文长度下实现了极低的 KV 缓存开销。

为什么源码注释写的是 MLA 而不是 HCA/CSA？ Attention 类（model.py L436-543）是 HCA 和 CSA 的统一实现，通过 compress_ratio 参数区分行为。 其 Q/KV/O 路径沿用了 V2/V3 的 MLA 设计模式（低秩投影 + 联合 latent），因此代码注释保留了 "MLA" 的说法。 但在架构层面，DeepSeek-V4 已不再是纯粹的 MLA——它用KV 压缩 + 稀疏索引替代了 V3 的完整 latent attention， 形成了 HCA 和 CSA 两种新的注意力变体。

与 V3 MLA 的关键差异： ① V3 的 KV 使用低秩压缩（kv_lora_rank），缓存中存的是 latent 向量，注意力时需要上投影恢复； V4 的 KV 直接投影到 head_dim=512 并存入缓存，然后通过 Compressor 做token 维度的池化压缩。 ② V3 对所有 KV 做全注意力；V4 引入滑动窗口 + 压缩 KV 的稀疏索引（sparse_attn）。 ③ V4 新增 Indexer 模块（仅 CSA 层），通过 Hadamard+FP4 量化模拟的轻量打分来选择 top-k 压缩 KV。

CSA 模块设计详解 (ratio=4)

CSA (Compressed Sparse Attention) 将每 4 个 token 压缩为 1 条 KV 记录， 但通过 Indexer 只选取最相关的 top-k=1024 条——"Sparse" 来自这里。 与 HCA 的最大区别有两点：
① Overlap 压缩：Compressor 的 wkv/wgate 输出 2× 维度（coff=2）， 借助 overlap_transform 让每个压缩窗口感知前后 8 个 token，平滑边界处的信息断裂。
② Indexer 打分：Indexer 拥有独立的 Compressor（头维 128，使用 Hadamard+FP4）， 对全部压缩 KV 进行轻量打分，按照当前 query 的相关性选出 top-k=1024 个位置。

def overlap_transform(self, tensor, value=0):
    # tensor: [b, n, ratio, 2*head_dim]  即 [b, n, 4, 1024]
    b, n, _, _ = tensor.size()
    ratio, d = self.compress_ratio, self.head_dim  # ratio=4, d=512

    new_tensor = tensor.new_full((b, n, 2*ratio, d), value)
    # 输出形状: [b, n, 8, 512]

    # slots 4-7（当前窗口）= tensor 的后 512 维（second half）
    new_tensor[:, :, ratio:] = tensor[:, :, :, d:]
    # tensor[:, :, :, d:] → [b, n, 4, 512]  每个 token 的"当前槽"

    # slots 0-3（前一窗口 overlap）= 前一 unflatten 块的前 512 维
    new_tensor[:, 1:, :ratio] = tensor[:, :-1, :, :d]
    # tensor[:, :-1, :, :d] → [b, n-1, 4, 512]  每个 chunk 的"overlap 槽"
    # 注: 第一个 chunk (n=0) 的 slots 0-3 保持 value (0 for kv, -inf for score)
    # 这使得第一个压缩块仅使用自身的 4 个 token，无 overlap 填充

    return new_tensor  # [b, n, 8, 512]

# 关键理解：
# wkv 输出 [b,s,1024]，前 512 维是该 token 作为"上一窗口边界信息"写入 overlap 槽
# 后 512 维是该 token 作为"当前窗口成员"写入当前槽
# 两路投影共享同一个 Linear，但感受野（slot 身份）不同，因此网络可以学习两种不同的压缩角色

门控池化机制：数学推导与 APE 设计

门控池化核心公式：
设窗口内 r 个 token 的原始表示为 x₀,…,xᵣ₋₁，对于 HCA r=128，CSA r=4 (或 overlap 后 8)：

kv_raw_i = W_kv · x_i　（Linear 投影，FP32）
gate_i = W_gate · x_i + ape_i　（加入可学习位置偏置 ape[i]）
weight_i = softmax({gate_j}_{j=0}^{r-1})_i　（在 r 个位置上 softmax）
kv_compressed = Σᵢ weight_i ⊙ kv_raw_i　（按元素加权求和）

APE（Absolute Position Encoding） 的作用： ape[i] ∈ ℝ⁵¹² 是第 i 个窗口位置的独立可学习向量，类似于传统绝对位置编码。 它让门控网络"知道"每个 token 在窗口内的相对位置，使得窗口边界（如首尾 token）可以 获得特殊的权重偏置，而不是所有位置都平等竞争。

与 Cross-Attention 的对比： 这相当于以 gate(x_i) 为 score、kv_raw(x_i) 为 value 做 self-pooling， 且 key 和 value 来自同一映射（wkv）。门控的 softmax 保证权重和为 1，输出为 kv_raw 的凸组合。

稀疏注意力核 (sparse_attn)

sparse_attn 是 DeepSeek-V4 的注意力计算核心，采用 FlashAttention 风格的在线 softmax， 但只对预选的 top-k KV 位置做注意力（而非全序列）。此外引入了可学习的 attention sink 偏置。

关键设计特点：

  • KV 是合并张量 [b, n, d] — 不拆分 K 和 V，沿用 MLA 的联合 latent 设计
  • 预计算索引 — topk_idxs 在 Indexer 或静态函数中生成，kernel 只做 gather + attention
  • Attention Sink — 每个头有一个可学习标量 attn_sink[h]，作为虚拟 token 的注意力分数，防止注意力分布塌缩
  • Head padding — 头数不足 16 时填充到 16 以保持 warp 对齐

    kv_block = gather(kv[b], idxs)             # [64, d] 按索引取 KV

    scores = q @ kv_block.T * scale            # [h, 64] 注意力分数
    # 注意: KV 是联合 latent 向量 (沿用 MLA 设计), Q×KV^T 直接得到 attention score
    # 而非传统的分别计算 Q×K^T 然后 ×V, 这是 latent attention 的核心

    # ─── 在线 Softmax (FlashAttention 风格) ───
    scores_max_prev = scores_max
    scores_max = max(scores_max, row_max(scores))
    scale_factor = exp(scores_max_prev - scores_max)  # 修正因子
    scores = exp(scores - scores_max)
    sum_exp = sum_exp * scale_factor + row_sum(scores)
    acc_o = acc_o * scale_factor + scores @ kv_block   # [h, d]
    # 同一个 kv_block 既用于计算 score 也用于加权求和
    # 这正是联合 KV latent 的高效之处: KV 是同一个张量

# ─── Attention Sink (kernel.py L345-346) ───
# attn_sink: [h] 每个头一个可学习标量, 作为虚拟 token 的注意力分数
sum_exp += exp(attn_sink[h] - scores_max)     # 加入虚拟 token 的 exp 贡献
# 不更新 acc_o: 虚拟 token 的 V=0, 只稀释 softmax 分母

# 防止 softmax 分布退化为对某个无关 token 的尖峰

KV 压缩器 (Compressor)

Compressor 通过学习型门控池化将连续 ratio 个 token 的 KV 压缩为一条记录。 对 CSA 层 (ratio=4)，使用 overlap 窗口机制产生更平滑的压缩边界。

源码位置：model.py L279-377

压缩原理

核心公式：kv_compressed = Σ(softmax(score) × kv)，其中 score 由 wgate 投影 + 可学习的位置编码 ape 得到。
Overlap (ratio=4): 每个压缩窗口实际看到 2×ratio=8 个 token（当前窗口 + 前一个窗口），前半部分是上一个窗口的"余光"， 后半部分是当前窗口的 token。这避免了硬边界导致的信息断裂。

    score = self.wgate(x)       # [b, s, head_dim] or [b, s, 2*head_dim](overlap)

KV 缓存内存布局

每层 Attention 维护一个统一的 kv_cache，前半为滑动窗口区域，后半为压缩缓存区域（仅 ratio>0 层有）。

稀疏索引器 (Indexer)

Indexer 仅在 CSA 层 (ratio=4) 中启用。它有自己的 Compressor（带 Hadamard 旋转 + FP4 量化模拟）， 用来构建一个轻量的"索引用 KV"。通过 Q 与压缩索引 KV 的点积打分，选出 top-k=1024 个最相关的压缩 KV 位置。

源码位置：model.py L380-433

Hadamard 旋转的作用： FP4 量化精度极低（仅 16 个可表示值），直接量化会损失大量信息。 Hadamard 旋转（rotate_activation，model.py L247-251）先做正交变换， 将信息均匀扩散到所有维度，消除稀疏/集中的激活模式。 旋转后的激活值分布更均匀，FP4 量化误差显著降低。 这是 Indexer 专用的——主 Compressor 不用 Hadamard（用 FP8 精度足够）。

    weights /= weights.sum(dim=-1, keepdim=True)   # 归一化
    weights *= self.route_scale                     # × 2.5 缩放
    return weights, indices

        # weight: [N, K//2] FP4 E2M1, weight.scale: [N, K//32] E8M0

    elif weight.dtype == torch.float8_e4m3fn:

        x, s = act_quant(x, block_size, scale_fmt, scale_dtype)
        return fp8_gemm(x, s, weight, weight.scale, scale_dtype)
        # weight.scale: [N//128, K//128] per-128×128 block scale

    else:
        # BF16 权重 (wo_a 已在 convert.py 中反量化)
        return F.linear(x, weight)

def hc_head(self, x, hc_fn, hc_scale, hc_base):
    # x: [b, s, 4, 7168] ← 最后一层的4条残差流
    # hc_fn: [4, 28672] ← 注意: 仅4行, 不是24行!
    # hc_scale: [1]  ← 标量 scale
    # hc_base: [4]   ← 4个 bias
    shape, dtype = x.size(), x.dtype
    x = x.flatten(2).float()     # [b, s, 28672] ← 4×7168 拼接
    rsqrt = torch.rsqrt(x.square().mean(-1, keepdim=True) + self.norm_eps)
    mixes = F.linear(x, hc_fn) * rsqrt
                                  # [b, s, 4] ← 线性投影到4维(每流一个权重)
    pre = torch.sigmoid(mixes * hc_scale + hc_base) + self.hc_eps
                                  # [b, s, 4] ← sigmoid 门控 + ε
    # 与 hc_pre 的关键区别:
    # 1. 只有 pre, 没有 post 和 comb (因为这是最后一步, 不需要分配回多流)
    # 2. 直接 sigmoid, 不走 Sinkhorn (计算更轻量)
    # 3. 单个 scale 标量, 而非 3 个 (pre/post/comb 各一个)
    y = torch.sum(pre.unsqueeze(-1) * x.view(shape), dim=2)
                                  # [b, s, 7168] ← 加权合并4条流
    return y.to(dtype)

def forward(self, x, hc_fn, hc_scale, hc_base, norm):
    x = self.hc_head(x, hc_fn, hc_scale, hc_base)  # [b,s,4,7168] → [b,s,7168]
    logits = self.get_logits(norm(x))                 # → RMSNorm → [b, 129280/TP]
    if world_size > 1:
        dist.all_gather(all_logits, logits)           # TP all_gather
        logits = torch.cat(all_logits, dim=-1)        # → [b, 129280]

def precompute_freqs_cis(dim, seqlen, original_seq_len, base, factor, beta_fast, beta_slow):
    # 基础频率: θ_i = base^(-2i/dim), i = 0, 1, ..., dim/2-1
    freqs = 1.0 / (base ** (torch.arange(0, dim, 2, dtype=torch.float32) / dim))
    # 对 dim=64: 32 个频率, 从 1/base^0 = 1 到 1/base^(62/64)

    if original_seq_len > 0:   # 启用 YaRN (仅压缩层)
        # 找到需要插值的频率维度范围 [low, high]
        # beta_fast=32: 低频端(对应长距离), 需要更多插值
        # beta_slow=1:  高频端(对应短距离), 保持原始频率
        low, high = find_correction_range(beta_fast, beta_slow, dim, base, original_seq_len)
        smooth = 1 - linear_ramp_factor(low, high, dim // 2)
        # smooth: [dim/2], 0→1 线性 ramp
        # smooth=0: 完全插值 (freqs/factor) → 低频, 适合长距离
        # smooth=1: 保持原始频率 → 高频, 保持局部精度
        freqs = freqs / factor * (1 - smooth) + freqs * smooth
        # 最终: 低频维度被 /factor 压缩 → 支持更长序列
        # 高频维度保持不变 → 局部位置编码精度不损失

    t = torch.arange(seqlen)
    freqs = torch.outer(t, freqs)              # [seqlen, dim/2]
    freqs_cis = torch.polar(torch.ones_like(freqs), freqs)
    # 复数表示: exp(i*θ), 用于高效旋转
    return freqs_cis

def apply_rotary_emb(x, freqs_cis, inverse=False):
    # x: [b, s, (h,) rope_dim] ← 仅后 64 维应用 RoPE
    # 原位操作: 直接修改输入张量
    y = x
    x = torch.view_as_complex(x.float().unflatten(-1, (-1, 2)))
    # [..., 64] → [..., 32] complex
    if inverse:
        freqs_cis = freqs_cis.conj()   # 反旋转: 用共轭复数
    x = torch.view_as_real(x * freqs_cis).flatten(-2)
    # 复数乘法 = 旋转, 展回实数
    y.copy_(x)   # 原位写回!
    return y

# 使用位置:
# Q: q[..., -64:] → 仅后64维(rope_head_dim)用RoPE, 前448维(nope_head_dim)不旋转
# KV: kv[..., -64:] → 同样仅后64维
# O: apply_rotary_emb(o[..., -64:], freqs, inverse=True) → 反旋转输出
反旋转输出（de-rotation）的作用： 联合 KV latent 中 KV 不拆分 K 和 V，RoPE 只应用于部分维度。 attention 输出 o = softmax(Q×KV^T) × KV 的后 64 维会带有 K 的 RoPE 旋转。 对输出做 apply_rotary_emb(inverse=True) 消除这个旋转偏移， 使后续 O 投影看到位置无关的表示。这是联合 KV latent attention 的关键步骤（model.py L534）。

def generate(model, prompt_tokens, max_new_tokens, eos_id, temperature=1.0):
    prompt_lens = [len(t) for t in prompt_tokens]
    total_len = min(model.max_seq_len, max_new_tokens + max(prompt_lens))
    tokens = torch.full((batch, total_len), -1, dtype=torch.long)
    # 右填充 -1, 不同长度 prompt 对齐

    prev_pos = 0
    for cur_pos in range(min(prompt_lens), total_len):
        # 第一次: tokens[:, 0:min_len] → Prefill
        # 之后:   tokens[:, prev:cur]   → Decode (1 token)
        logits = model.forward(tokens[:, prev_pos:cur_pos], prev_pos)
        # logits: [b, vocab_size=129280] — 只返回最后位置

        if temperature > 0:
            next_token = sample(logits, temperature)   # Gumbel-max
        else:
            next_token = logits.argmax(dim=-1)         # Greedy

        # 对仍在 prompt 范围内的位置,用 ground truth 覆盖
        next_token = torch.where(prompt_mask[:, cur_pos], tokens[:, cur_pos], next_token)
        tokens[:, cur_pos] = next_token
        finished |= (~prompt_mask[:, cur_pos]) & (next_token == eos_id)
        prev_pos = cur_pos
        if finished.all(): break

FP4→FP8 转换 (cast_e2m1fn_to_e4m3fn)

无损转换原理： FP4 (E2M1) 最大值 6.0，乘以 per-32 E8M0 scale 后，最大 6.0 × 2^6 = 384 < 448 (FP8 max)。 所以可以将 FP4 值 × (原 scale / 新 block-scale) 得到一个 FP8 可精确表示的值，同时用更粗粒度的 per-128×128 block scale。
