RoPE (Rotary Position Embedding) 由苏剑林在 2021 年的 RoFormer 论文中提出。它通过旋转变换将位置信息注入到 Query 和 Key 向量中，使得两个 token 的注意力分数仅取决于它们的相对距离，而非绝对位置。

如今，几乎所有主流大语言模型（LLaMA、GPT-NeoX、Qwen、DeepSeek、Mistral 等）都使用 RoPE 作为位置编码方案。

为什么 Transformer 需要位置编码？

Transformer 的自注意力机制本质上是一个集合操作（set operation）——它对输入 token 做加权求和，但完全不关心 token 的顺序。如果不加位置编码，"猫追狗" 和 "狗追猫" 在 Transformer 眼中是完全一样的。

没有位置编码

Attention(Q, K, V) 的结果与输入顺序无关。对于排列 π：

\(\text{Attention}(\pi(X)) = \pi(\text{Attention}(X))\)

"I love you" = "you love I" = "love I you"

有位置编码

位置编码打破了排列等变性，使模型能区分不同顺序：

\(f(x,\ \text{pos}) \neq f(x,\ \text{pos}')\)

"I love you" ≠ "you love I"

2. 直觉理解：为什么是旋转？

核心直觉：旋转角度 = 位置

想象一个时钟：时针指向不同的角度代表不同的时间。RoPE 的思路完全类似——把向量旋转不同的角度来表示不同的位置。

  • 位置 0 的 token：不旋转（旋转 0°）
  • 位置 1 的 token：旋转 θ°
  • 位置 2 的 token：旋转 2θ°
  • 位置 \(m\) 的 token：旋转 \(m\theta°\)

为什么旋转能编码"相对"位置？

RoPE 最精妙的地方在于：当计算 Query 和 Key 的内积时，旋转角度的差值自然体现了两个 token 的相对距离。

\[\langle R(\textcolor{#e64980}{m}\theta) \cdot q,\; R(\textcolor{#0c8599}{n}\theta) \cdot k \rangle = \langle R((\textcolor{#e64980}{m} - \textcolor{#0c8599}{n})\theta) \cdot q,\; k \rangle\] 内积只依赖相对距离 \((m - n)\)，而非绝对位置 \(m\) 或 \(n\)
直觉类比：音乐中的移调

两个音符之间的"音程"（相对关系）不会因为你把整首曲子移调而改变。C-E 是大三度，D-F# 也是大三度。RoPE 中的旋转就像移调——绝对"音高"（位置）变了，但两个 token 之间的"音程"（相对距离）保持不变。

3. 数学原理

3.1 从 2D 旋转矩阵开始

在二维平面上旋转一个向量 \((x_1, x_2)\)，只需要乘以一个旋转矩阵：

\[R(\theta) = \begin{pmatrix} \cos\theta & -\sin\theta \\ \sin\theta & \cos\theta \end{pmatrix}\] 2D 旋转矩阵：将向量逆时针旋转 \(\theta\) 角

关键性质：

  • 保范性：旋转不改变向量长度，\(\|R(\theta)x\| = \|x\|\)
  • 可加性：\(R(\alpha) \cdot R(\beta) = R(\alpha + \beta)\)
  • 正交性：\(R(\theta)^\top = R(-\theta) = R(\theta)^{-1}\)

对于位置 \(m\) 的 token，RoPE 将其 Query/Key 向量旋转 \(m\theta\) 角度：

\[q'_m = R(m\theta) \cdot q_m = \begin{pmatrix} \cos(m\theta) & -\sin(m\theta) \\ \sin(m\theta) & \cos(m\theta) \end{pmatrix} \begin{pmatrix} q_1 \\ q_2 \end{pmatrix}\]

3.2 推广到高维：分组旋转

实际的 Query/Key 向量是 \(d\) 维的（如 128 维）。RoPE 将 \(d\) 维向量两两分组，每组用不同的频率旋转：

完整的 \(d\) 维 RoPE 旋转矩阵是一个分块对角矩阵：

\[R_d(m) = \operatorname{diag}\!\bigl(R(m\theta_1),\, R(m\theta_2),\, \ldots,\, R(m\theta_{d/2})\bigr)\] \(d/2\) 个独立的 2D 旋转，每个频率不同

其中频率按照几何级数递减：

\[\theta_i = \text{base}^{-2(i-1)/d}, \quad i = 1, 2, \ldots, d/2, \quad \text{base} = 10000\] 默认 base = 10000，产生从高频到低频的一系列旋转频率

3.3 复数形式：更优雅的表达

将每对相邻元素 \((q_{2i-1}, q_{2i})\) 看作一个复数 \(q_{2i-1} + q_{2i} \cdot i\)，则旋转就变成了复数乘法：

\[q'_i = q_i \cdot e^{im\theta_i} = (q_{2i-1} + q_{2i} \cdot i) \cdot \bigl(\cos(m\theta_i) + \sin(m\theta_i) \cdot i\bigr)\] 复数乘以单位圆上的点 = 旋转！这就是 RoPE 最简洁的形式

下面逐步说明这个转换的全过程：

1

相邻两个实数 → 一个复数（仅 reshape，不改变数值）

实数向量 q（d 维）:
[ q₁,  q₂ | q₃,  q₄ | q₅,  q₆ | ... | q_(d-1), q_d ]
  第1对        第2对        第3对              第d/2对
       ↓  reshape(*shape[:-1], -1, 2) + view_as_complex
复数向量（d/2 个复数）:
[ q₁+q₂·i,   q₃+q₄·i,   q₅+q₆·i,   ...   q_(d-1)+q_d·i ]
    q̃₁           q̃₂           q̃₃               q̃_(d/2)

这不是近似，只是对同一块内存的不同解读方式。PyTorch 一行完成：
torch.view_as_complex(q.reshape(*q.shape[:-1], -1, 2))

2

旋转因子 = 单位圆上的复数

\[e^{im\theta_i} = \cos(m\theta_i) + \sin(m\theta_i) \cdot i\] 模长为 1，在复平面单位圆上，代表旋转角度 \(m\theta_i\)

这正是旋转矩阵 cos/sin 元素的来源——复数形式和矩阵形式是同一旋转的两种写法。

3

复数乘法完整展开（利用 i² = −1）

\[\begin{aligned} \tilde{q}_i \times e^{im\theta_i} &= (q_{2i-1} + q_{2i}\cdot i) \times (\cos(m\theta_i) + \sin(m\theta_i)\cdot i) \\[4pt] &= \textcolor{#364fc7}{q_{2i-1}\!\cdot\!\cos(m\theta_i)} + \textcolor{#e64980}{q_{2i-1}\!\cdot\!\sin(m\theta_i)\!\cdot\! i} + \textcolor{#e64980}{q_{2i}\!\cdot\!\cos(m\theta_i)\!\cdot\! i} + \textcolor{#7048e8}{q_{2i}\!\cdot\!\sin(m\theta_i)\!\cdot\!\mathbf{i^2}} \\[4pt] &= \textcolor{#364fc7}{(q_{2i-1}\cdot\cos(m\theta_i) - q_{2i}\cdot\sin(m\theta_i))} + \textcolor{#e64980}{(q_{2i-1}\cdot\sin(m\theta_i) + q_{2i}\cdot\cos(m\theta_i))\cdot i} \end{aligned}\] 实部 = \(q'_{2i-1}\)  |   虚部 = \(q'_{2i}\)  |   \(i^2 = -1\)，第4项 sin 符号翻转后并入实部
4

写回实数形式，与 3.1 节的旋转矩阵完全等价

\[\begin{aligned} q'_{2i-1} &= q_{2i-1} \cdot \cos(m\theta_i) - q_{2i} \cdot \sin(m\theta_i) \\ q'_{2i} &= q_{2i-1} \cdot \sin(m\theta_i) + q_{2i} \cdot \cos(m\theta_i) \end{aligned}\] 与 3.1 节的 2×2 旋转矩阵乘法结果完全一致
为什么复数形式在代码中更常用？

复数乘法和矩阵乘法的算术运算量完全相同——展开后都是 4 次乘法 + 2 次加减。复数形式的真正优势在于代码简洁性和工程效率：

矩阵形式展开

# 2×2 矩阵 × 2 维向量
# [cos, -sin] [q1]   [q1·cos - q2·sin]
# [sin,  cos] [q2] = [q1·sin + q2·cos]

out1 = q1*cos - q2*sin  # 2 次乘 + 1 次减

# 合计: 4 次乘 + 2 次加减

# = q1·cos + q1·sin·i

# 合计: 同样 4 次乘 + 2 次加减

复数乘法只是把同样的 4 次乘法"包装"在一个运算符里，CPU/GPU 底层执行的指令完全一样。

3.4 Q·K 内积：相对位置的数学证明

现在来证明为什么 RoPE 能编码相对位置。设位置 \(m\) 的 Query 和位置 \(n\) 的 Key，目标是证明：

\[\langle R(m\theta)\,q,\; R(n\theta)\,k \rangle = \langle R((m-n)\theta)\,q,\; k \rangle\] 内积只依赖相对距离 \((m-n)\)，而非绝对位置 \(m\) 或 \(n\)
展开完整推导（4 步）

推导依赖旋转矩阵的两个核心性质： 正交性 \(R(\alpha)^{-1} = R(\alpha)^\top = R(-\alpha)\)，以及 可加性 \(R(\alpha) R(\beta) = R(\alpha+\beta)\)。

1

内积 → 转置形式

\[\begin{aligned} &\langle R(m\theta)\,q,\; R(n\theta)\,k \rangle \\ &= \bigl[R(m\theta)\,q\bigr]^\top \bigl[R(n\theta)\,k\bigr] \\ &= q^T R(m\theta)^\top R(n\theta)\,k \end{aligned}\]

内积写成矩阵转置形式，把两个旋转矩阵分离出来。

2

正交性：R(α)ᵀ = R(−α)

\[= q^T \textcolor{#e64980}{R(-m\theta)}\, R(n\theta)\,k\]

旋转矩阵是正交矩阵：\(R(\theta)^\top R(\theta) = I\)，故 \(R(\theta)^\top = R(\theta)^{-1} = R(-\theta)\)。
因此 \(R(m\theta)^\top\) 直接替换为 \(R(-m\theta)\)。

3

可加性：R(α) R(β) = R(α+β)

\[= q^T \textcolor{#7048e8}{R((n-m)\theta)}\,k\]

\(R(-m\theta)\,R(n\theta) = R((-m+n)\theta) = R((n-m)\theta)\)。
两次旋转合并为一次，角度直接相加。

4

写回内积形式，整理符号

\[\begin{aligned} &= q^T \bigl[R((m-n)\theta)\bigr]^{-1} k \\ &= \bigl[R((m-n)\theta)\,q\bigr]^\top k \\ &= \textcolor{#2b8a3e}{\langle R((m-n)\theta)\,q,\; k \rangle} \end{aligned}\]

\(R((n-m)\theta) = [R((m-n)\theta)]^{-1}\)，再将矩阵移到左侧向量上，即得目标等式。
结果中 n、m 仅以差值 \((m-n)\) 出现，绝对位置消失。

几何直觉：坐标系整体旋转

把整个坐标系逆向旋转 \(n\theta\)（乘以 \(R(-n\theta)\)）——夹角不变，内积不变。旋转后 k 回到原始方向，q 则变成 \(R((m-n)\theta)\,q\)，只携带两者的相对角度差，绝对位置 m、n 彻底抵消。

关键结论

经过 RoPE 旋转后，Q 和 K 的内积（即注意力分数）只是相对距离 \((m-n)\) 的函数。无论 token 在序列中的绝对位置如何，只要两个 token 之间的距离相同，它们的注意力分数就相同。

4. 频率设计与长度外推

4.1 频率基底 θ 的设计

RoPE 的频率公式 \(\theta_i = \text{base}^{-2(i-1)/d}\) 的设计灵感来自原始 Transformer 的正弦位置编码，但有本质区别：

正弦位置编码 (Sinusoidal)

将 sin/cos 值加到 token 嵌入上

加法破坏了向量的内积结构

位置信息和语义信息混合

RoPE

用 sin/cos 构造旋转矩阵，乘以 Q/K

旋转保持内积的"相对位置"特性

位置信息融入注意力计算本身

不同维度对 (pair) 的频率形成一个从高频到低频的频谱：

频率的直觉：多尺度位置编码

类比十进制数字：个位数变化最快（高频），十位次之，百位更慢（低频）。RoPE 中前几个维度对像"秒针"（快速旋转，分辨近距离），后面的维度对像"时针"（缓慢旋转，分辨远距离）。这种多尺度编码使得 RoPE 既能区分相邻 token，也能感知远距离依赖。

4.2 长度外推：超越训练长度

RoPE 的一大优势是支持长度外推——模型能泛化到比训练时更长的序列。方法是调整 base 参数：

方法策略base 值效果
原始 RoPE—10,000训练长度内表现好
Code LLaMA增大 base1,000,00016K → 100K
DeepSeek-V4增大 base10,000,000256K
YaRN分段缩放动态高倍外推
NTK-aware动态 base按长度调整无需微调外推

增大 base 的直觉：base 越大，所有频率越低，旋转越慢。这意味着在更长的序列上，旋转角度的变化更加平缓，避免了高频维度"绕圈太多"导致的周期性混淆。

\[\text{base} \uparrow \;\Rightarrow\; \theta_i \downarrow \;\Rightarrow\; \text{每个位置的旋转角度更小} \;\Rightarrow\; \text{可表示更长序列}\]

5. RoPE 的关键优势

相对位置编码

注意力分数仅依赖 token 间相对距离，天然适合语言建模中的平移不变性需求

保范性

旋转不改变向量长度，不会引入额外的 scale 偏差，训练更稳定

远距离衰减

相对距离越大，高频分量旋转越多，内积自然衰减，模拟局部性偏好

可扩展性

通过调整 base 或分段缩放，灵活外推到任意长度，无需修改模型结构

远距离衰减的直觉解释

当两个 token 距离较远时，每个维度对的旋转角度差 \((m-n)\theta_i\) 都很大。高频维度的 cos 值会剧烈振荡、正负抵消，使得这些维度对内积的贡献趋近于零。只有最低频的几个维度还能保持一致的方向。

这产生了一种天然的局部性偏好：近距离 token 对的内积更大（更多维度"对齐"），远距离 token 对的内积更小。这与语言中"近处的词通常更相关"的先验一致。

6.1 频率计算：compute_default_rope_parameters

在 LlamaRotaryEmbedding.__init__ 中，如果 rope_type == "default"，则调用下面这个静态方法来计算逆频率 inv_freq：

# 源码: models/llama/modeling_llama.py — LlamaRotaryEmbedding 类 (L73-120)

class LlamaRotaryEmbedding(nn.Module):
    inv_freq: torch.Tensor  # fix linting for `register_buffer`

    def __init__(self, config: LlamaConfig, device=None):
        super().__init__()
        self.max_seq_len_cached = config.max_position_embeddings
        self.original_max_seq_len = config.max_position_embeddings
        self.config = config

        # 根据 rope_type 选择频率初始化函数
        self.rope_type = self.config.rope_parameters["rope_type"]
        rope_init_fn: Callable = self.compute_default_rope_parameters
        if self.rope_type != "default":
            # 非默认类型 → 从全局注册表中取 (linear/dynamic/yarn/longrope/llama3)
            rope_init_fn = ROPE_INIT_FUNCTIONS[self.rope_type]
        inv_freq, self.attention_scaling = rope_init_fn(self.config, device)

        # 将 inv_freq 注册为非持久化 buffer（不会被 state_dict 保存）
        self.register_buffer("inv_freq", inv_freq, persistent=False)
        self.register_buffer("original_inv_freq", inv_freq.clone(), persistent=False)

    # ── 默认频率计算 ──
    @staticmethod
    def compute_default_rope_parameters(
        config: LlamaConfig | None = None,
        device=None, seq_len: int | None = None,
    ) -> tuple[torch.Tensor, float]:
        base = config.rope_parameters["rope_theta"]        # 默认 10000.0
        dim = getattr(config, "head_dim", None) \
              or config.hidden_size // config.num_attention_heads
            # LLaMA-2-7B: 4096 // 32 = 128

        attention_factor = 1.0  # 默认 RoPE 不做注意力缩放

        # 核心公式: inv_freq[i] = 1 / base^(2i/d)
        inv_freq = 1.0 / (
            base ** (torch.arange(0, dim, 2, dtype=torch.int64)
                     .to(device=device, dtype=torch.float) / dim)
        )
            # [head_dim/2] — 从高频到低频的逆频率序列
            # 例: dim=128 → [64]
            # inv_freq[0]  = 1/10000^(0/128)   = 1.0       (最高频)
            # inv_freq[1]  = 1/10000^(2/128)    ≈ 0.7499
            # inv_freq[63] = 1/10000^(126/128)  ≈ 0.000107  (最低频)
        return inv_freq, attention_factor

所有函数共享相同签名 (config, device, seq_len, layer_type) → (inv_freq, attention_factor)，模型无需关心具体缩放策略。

6.1.1 RotaryEmbedding.forward：角度矩阵 → cos/sin

inv_freq 预计算后存为 buffer，forward 每次被调用时根据 position_ids 算出实际的 cos/sin 值：

# 源码: models/llama/modeling_llama.py — LlamaRotaryEmbedding.forward (L122-135)

    @torch.no_grad()
    @dynamic_rope_update  # 装饰器：若 rope_type 含 "dynamic"，先更新 inv_freq
    def forward(self, x, position_ids):
        # inv_freq: [head_dim/2]
        # position_ids: [batch, seq_len]

        # 扩展为可做批量矩阵乘法的形状
        inv_freq_expanded = self.inv_freq[None, :, None].float() \
            .expand(position_ids.shape[0], -1, 1).to(x.device)
            # [batch, head_dim/2, 1]
        position_ids_expanded = position_ids[:, None, :].float()
            # [batch, 1, seq_len]

        # 核心：矩阵乘法计算所有 (位置, 维度对) 的旋转角度
        with maybe_autocast(device_type=..., enabled=False):  # 强制 float32
            freqs = (inv_freq_expanded.float()
                     @ position_ids_expanded.float()).transpose(1, 2)
                # [batch, head_dim/2, 1] @ [batch, 1, seq_len]
                # → [batch, head_dim/2, seq_len] → transpose → [batch, seq_len, head_dim/2]
                # freqs[b][m][i] = position_ids[b][m] × inv_freq[i] = m·θᵢ

            emb = torch.cat((freqs, freqs), dim=-1)
                # [batch, seq_len, head_dim] — 沿最后维度复制一份，供 rotate_half 使用

            cos = emb.cos() * self.attention_scaling
            sin = emb.sin() * self.attention_scaling
                # [batch, seq_len, head_dim]

        return cos.to(dtype=x.dtype), sin.to(dtype=x.dtype)
步骤操作Shape 变化数学含义
1inv_freq[None, :, None][1, d/2, 1]准备做 batch matmul
2position_ids[:, None, :][B, 1, S]位置序列
3matmul + transpose[B, S, d/2]freqs[m][i] = m · θᵢ
4cat((freqs, freqs))[B, S, d]复制一份以匹配 head_dim
5.cos() / .sin()[B, S, d]最终的旋转因子

6.2 应用旋转到 Q/K：rotate_half + apply_rotary_pos_emb

Transformers 中 LLaMA 的实现不使用复数运算，而是用纯实数的 rotate_half 技巧。这是工业界最主流的实现方式：

# 源码: models/llama/modeling_llama.py (L138-168)

def rotate_half(x):
    """Rotates half the hidden dims of the input."""
    x1 = x[..., : x.shape[-1] // 2]    # 前半: q₁, q₂, ..., q_{d/2}
    x2 = x[..., x.shape[-1] // 2 :]    # 后半: q_{d/2+1}, ..., q_d
    return torch.cat((-x2, x1), dim=-1)
    # 输出: [-q_{d/2+1}, ..., -q_d, q₁, ..., q_{d/2}]
    # 本质: 每对 (qᵢ, q_{i+d/2}) 做 90° 旋转 → (-q_{i+d/2}, qᵢ)


def apply_rotary_pos_emb(q, k, cos, sin, unsqueeze_dim=1):
    """Applies Rotary Position Embedding to the query and key tensors."""
    # q, k: [batch, n_heads, seq_len, head_dim]
    # cos, sin: [batch, seq_len, head_dim]
    cos = cos.unsqueeze(unsqueeze_dim)  # → [batch, 1, seq_len, head_dim]
    sin = sin.unsqueeze(unsqueeze_dim)  # → [batch, 1, seq_len, head_dim] (广播到所有 head)

    # 核心旋转公式（等价于 2×2 旋转矩阵 × 向量对）
    q_embed = (q * cos) + (rotate_half(q) * sin)
    k_embed = (k * cos) + (rotate_half(k) * sin)
    return q_embed, k_embed
🔍 展开：为什么 q * cos + rotate_half(q) * sin 等价于旋转矩阵？

对于一对元素 \((q_i, q_{i+d/2})\)，rotate_half 会将它们变为 \((-q_{i+d/2}, q_i)\)。代入公式：

\[\begin{aligned} q'_i &= q_i \cdot \cos(m\theta) + (-q_{i+d/2}) \cdot \sin(m\theta) = q_i \cos(m\theta) - q_{i+d/2} \sin(m\theta) \\ q'_{i+d/2} &= q_{i+d/2} \cdot \cos(m\theta) + q_i \cdot \sin(m\theta) = q_i \sin(m\theta) + q_{i+d/2} \cos(m\theta) \end{aligned}\]

这正是 2×2 旋转矩阵 \(\begin{pmatrix}\cos\theta & -\sin\theta \\ \sin\theta & \cos\theta\end{pmatrix}\) 作用在 \((q_i, q_{i+d/2})\) 上的结果。

注意：LLaMA 的配对方式是"前半 + 后半"（即 \(q_i\) 与 \(q_{i+d/2}\) 配对），而非"相邻配对"（\(q_{2i-1}\) 与 \(q_{2i}\)）。两种方式数学上等价，只要 cos/sin 的排列与之一致。

在 Attention 中的调用位置

在 LlamaAttention.forward 中，RoPE 在线性投影之后、KV 缓存更新之前应用：

# 源码: models/llama/modeling_llama.py — LlamaAttention.forward (L262-270)

# 1. 线性投影

# 2. 应用 RoPE（cos, sin 来自 LlamaModel 中的 self.rotary_emb）

# 3. 更新 KV 缓存（RoPE 后的 key 被缓存）

6.5 Cohere 变体：交替配对 (interleave) 方式

值得注意的是，不同模型对 head_dim 的配对方式不同。Cohere 模型使用"相邻元素交替配对"，而非 LLaMA 的"前半/后半"配对：

# 源码: models/cohere/modular_cohere.py (L69-91)

# Cohere 的 RotaryEmbedding：用 repeat_interleave 代替 cat
class CohereRotaryEmbedding(LlamaRotaryEmbedding):
    def forward(self, x, position_ids):
        ...
        freqs = (inv_freq_expanded.float() @ position_ids_expanded.float()).transpose(1, 2)
        emb = torch.repeat_interleave(freqs, 2, dim=-1)  # ← 关键区别！
        # LLaMA: cat((freqs, freqs))   → [θ₁,θ₂,...,θ₁,θ₂,...]
        # Cohere: repeat_interleave(2) → [θ₁,θ₁,θ₂,θ₂,θ₃,θ₃,...]
        ...

# Cohere 的 rotate_half：交替取元素
def rotate_half(x):
    x1 = x[..., ::2]           # 偶数索引: q₀, q₂, q₄, ...
    x2 = x[..., 1::2]          # 奇数索引: q₁, q₃, q₅, ...
    rot_x = torch.stack([-x2, x1], dim=-1).flatten(-2)
    return rot_x
    # 输出: [-q₁, q₀, -q₃, q₂, -q₅, q₄, ...]
    # 配对方式: (q₀,q₁), (q₂,q₃), ... — 相邻元素配对

LLaMA 方式

前半/后半配对

向量 [q₁ q₂ q₃ q₄ | q₅ q₆ q₇ q₈]

配对: (q₁,q₅) (q₂,q₆) (q₃,q₇) (q₄,q₈)

cos/sin 布局: cat((freqs, freqs))

Cohere 方式

相邻元素配对

向量 [q₁ q₂ | q₃ q₄ | q₅ q₆ | q₇ q₈]

配对: (q₁,q₂) (q₃,q₄) (q₅,q₆) (q₇,q₈)

cos/sin 布局: repeat_interleave(2)

两种配对方式数学上完全等价（只是维度排列不同），但工程实现和 kernel 优化上各有取舍。LLaMA 的 cat 方式在大多数 GPU kernel 中更高效。

6.6 进阶：Dynamic NTK 缩放（长度外推）的实际代码

当 rope_type="dynamic" 时，@dynamic_rope_update 装饰器会在 forward 中自动检测是否需要更新 inv_freq：

# 源码: modeling_rope_utils.py — _compute_dynamic_ntk_parameters (L257-324)

def _compute_dynamic_ntk_parameters(config, device, seq_len=None, ...):
    base = rope_parameters_dict["rope_theta"]          # 原始 base
    factor = rope_parameters_dict["factor"]
    dim = int(head_dim * partial_rotary_factor)

    # 关键：根据当前序列长度动态调整 base
    base = base * (
        (factor * seq_len / config.max_position_embeddings) - (factor - 1)
    ) ** (dim / (dim - 2))
    # 当 seq_len > max_position_embeddings 时，base 增大 → 频率降低 → 旋转变慢
    # 这就是 NTK-aware 缩放的核心公式（来自 Reddit 用户 /u/bloc97）

    inv_freq = 1.0 / (base ** (torch.arange(0, dim, 2, ...).float() / dim))
    return inv_freq, attention_factor

这对应第 4 节中的长度外推原理：base ↑ → θᵢ ↓ → 每步旋转角更小 → 可表示更长序列。

这张图在说什么？

图中有两条线：蓝色实线是实际内积（快速振荡），粉色虚线是振幅包络（移动均值）。包络线总体向下——振荡越来越密集，但幅度越来越小。这个衰减是从旋转数学中"免费"得到的性质，无需任何额外设计。

\[\langle R(d\,\theta)\,q,\; k \rangle \quad \xrightarrow{d \uparrow} \quad \text{振幅整体下降}\] 对任意随机 Q/K，内积的振荡幅度随相对距离 \(d = |m-n|\) 增大而整体衰减

为什么会衰减？

RoPE 把 \(d\) 维向量分成 \(d/2\) 组，每组的旋转频率 \(\theta_i\) 不同：

维度对频率 \(\theta_i\)距离为 \(d\) 时的旋转角对内积的贡献
前几组（高频） \(\approx 1.0\) \(d \times 1.0\)，迅速绕满一圈 正负交替，相互抵消
中间组 \(\approx 0.01\) 旋转较慢 部分有效
最后几组（低频） \(\approx 10^{-4}\) 几乎不动 方向保持一致，贡献稳定

当距离 \(d\) 增大时，高频维度的 \(\cos(d\,\theta_i)\) 快速正负交替并相互抵消，能"对齐"的维度越来越少，最终只有少数低频维度还能提供稳定的内积贡献——振幅包络因此持续下降。

天然的局部性偏好（Locality Bias）

这个衰减不需要像 ALiBi 那样手动加距离惩罚项——RoPE 从数学结构上就自然产生了：

  • 近距离 token 对：旋转角小，各维度方向对齐，内积大 → 注意力强
  • 远距离 token 对：高频维度快速振荡抵消，内积整体衰减 → 注意力弱

这与"近处的词通常更相关"的语言先验完全吻合，且是零额外参数实现的。

📌 在全文中的位置

第 5 节以"远距离衰减"作为 RoPE 四大优势之一给出了理论说明；本节用交互图给出经验验证——把抽象的 \(\cos\) 振荡分析变成可以拖动滑块亲眼看到的图形。尝试调大 base：更大的 base 使所有频率变低，衰减曲线会更平缓，也正是长度外推方案的核心思路。

10. 交互式 Demo：attention_scaling 的外推补偿

上一节的内积衰减是 RoPE 的好性质。但当我们把上下文从 4K 外推到 128K 时，会出现一个坏副作用：query 要 attend 的 key 变多了，softmax 把概率质量摊薄到成百上千个背景 token 上，注意力分布变"钝"、熵升高，真正相关的 token 反而抢不到权重。attention_scaling 就是用来补偿这个副作用的。

它在代码里长这样

self.attention_scaling（RoPE 初始化函数返回的 attention_factor）是一个直接乘在 cos/sin 上的标量：

# modeling_rope_utils.py — 初始化时由 rope_init_fn 返回
inv_freq, self.attention_scaling = rope_init_fn(config, device, ...)

# modeling_llama.py:132 — forward 中乘进 cos/sin
cos = emb.cos() * self.attention_scaling
sin = emb.sin() * self.attention_scaling

由于 apply_rotary_pos_emb 里 query 和 key 都用同一组 cos/sin 旋转，把 cos/sin 乘上因子 \(s\) 会让 \(q_{\text{embed}}\) 和 \(k_{\text{embed}}\) 各放大 \(s\) 倍——两者都线性依赖 cos/sin。于是它们的内积被放大 \(s\times s = s^2\) 倍：attention logit \(q\!\cdot\!k\) 被整体放大 \(s^2\) 倍，效果等同于给 softmax 降温、把分布重新“锐化”。

\[q_{\text{embed}}\cdot k_{\text{embed}} \;\longrightarrow\; (s\,q_{\text{embed}})\cdot(s\,k_{\text{embed}}) = s^2\,(q_{\text{embed}}\cdot k_{\text{embed}})\] q、k 共用同一组被缩放的 cos/sin，各自放大 s 倍，故内积放大 s² 倍
\[\text{softmax}\big(s^2\cdot(q\!\cdot\!k)\big),\qquad s = \texttt{attention\_scaling} \ge 1\] s 越大 → logit 差距被放大 (∝ s²) → softmax 越尖锐 → 熵越低
⚠️ 因此 attention_scaling 是"温度的平方根"

若想让 logit 得到温度因子 \(t\)（即 \(\text{softmax}(t\cdot q\!\cdot\!k)\)），需要设 attention_scaling \(=\sqrt{t}\)。YaRN 存下的 attention_factor 就是这个 \(s=\sqrt{t}\)，真正作用在注意力分数上的放大是 \(s^2\)。

YaRN 的分段策略细节

YaRN 将频率维度分为三段：

  • 低频段（波长 > 原始训练长度）：直接缩放（NTK 方式）
  • 中频段：NTK 和线性插值的混合
  • 高频段（波长 << 训练长度）：保持不变

这样做的理由是：高频维度编码的是近距离关系，训练时已经见过足够多的模式，不需要调整；而低频维度编码远距离关系，是外推时需要重点调整的部分。

12. 总结

一句话总结

RoPE 把位置编码从 "给 token 贴标签"（绝对编码）变成了 "让 token 转起来"（旋转编码）。每个 token 被旋转的角度取决于它的位置，而两个 token 注意力分数只取决于它们旋转角度的差——也就是相对距离。这个简单而优雅的想法，让模型既能精确感知 token 顺序，又能灵活适应不同长度的序列。
