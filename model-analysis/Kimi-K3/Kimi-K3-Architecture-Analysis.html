01 · conclusion first

用三条轴理解 Kimi K3

论文把架构组织为 token、layer、channel 三种 mixing。源码中的模块边界与这套抽象基本一致。

↔

序列轴 · Token Mixing

每 4 层使用 3 个线性复杂度 KDA，再用 1 个全局 Gated MLA 校正；末层额外保证一次全局注意力。长程效率与全局内容交互各司其职。

↕

深度轴 · Layer Mixing

Block AttnRes 不再只接收“上一层的统一残差”。每个子层用可学习伪查询，对 embedding、历史块和当前块部分和做深度 softmax 检索。

⋮

宽度轴 · Channel Mixing

共享专家保留 7168 维通路；896 个路由专家在 3584 维 latent 空间工作，每个 token 选择 16 个。SiTU‑GLU 与 RMSNorm 抑制超高稀疏度下的激活爆炸。

核心设计判断：KDA、AttnRes、LatentMoE 并非三项孤立技巧。它们分别缓解序列长度、网络深度、模型宽度的扩展瓶颈；MoonViT‑V2 只负责把视觉变成共享 embedding 空间中的 token，后续推理完全交给同一语言主干。

04 · sequence mixing

KDA：带逐通道遗忘的 Delta Rule

69 个 KDA 层承担大部分长上下文 token mixing。训练/prefill 用 chunk 并行，单 token decode 切到 recurrent kernel。

源码中的计算路径

x → Q / K / V projections7168 → 96 × 128；三条独立无偏置线性映射
ShortConv(k=4) → SiLUQ、K、V 各有一条短卷积；Q/K 在 KDA kernel 中做 L2Norm
Decay α + write strength β低秩 7168→128→12288 生成逐通道 decay；7168→96 生成逐 head β
Chunk KDA / Fused Recurrent KDAprefill/训练并行；decode 维护每层 recurrent state 与三条 conv state
Head RMSNorm + full-rank output gateσ(Wg x) ⊙ RMSNorm(õ) → Wo → 7168

单头递推

Sₜ = (I − βₜkₜkₜᵀ) Diag(αₜ) Sₜ₋₁ + βₜkₜvₜᵀ
õₜ = Sₜᵀqₜ

直觉上先按通道遗忘旧状态，再用 delta rule 修正键 kₜ 对应的记忆，最后用 qₜ 读取。状态大小不随上下文长度增长。

K3 的关键改动：下界化 log-decay

g = −5 · sigmoid(exp(A) · z),   α = exp(g)
因此 α ∈ (e⁻⁵, 1)，16-token tile 的累计 log-decay ∈ (−80, 0)
为什么它适合 1M context：KDA 的 decode 缓存是固定尺寸 recurrent state，而不是随 token 数增长的 KV 序列。代价是循环状态本身很大，且 prefix cache / speculative decoding 需要专门的状态快照与回放设计；论文 §5.4 进一步描述了生产部署优化，当前 HF 文件只是参考实现。

05 · periodic global attention

Gated MLA：周期性全局校正

KDA 注重线性长程混合，MLA 保留不受局部递推限制的全局 content-to-content attention。K3 的所有语言注意力均为 NoPE。

低秩 Q / KV 路径

Q: 7168 → 1536 → RMSNorm → 96×192q_lora_rank=1536；每头 128 NoPE content + 64 compatibility slot
KV: 7168 → (512 + 64)512 维 latent 经 RMSNorm 与 up projection 还原每头 K(content=128, V=128)
Global causal attention96 heads；q head=192，v head=128；FlashAttention 路径临时 pad V
σ(Wg x) ⊙ attention output → Wofull-rank channel-wise output gate

06 · depth mixing

AttnRes：让层去“注意”深度

下方权重仅用于解释机制，不是 checkpoint 实测值。拖动目标层，观察可用的块级来源如何增加。

Block Attention Residual

αᵢ→ₗ = softmaxᵢ(wₗᵀ RMSNorm(vᵢ))
hₗ = Σᵢ αᵢ→ₗ · vᵢ

K3 每 12 层把块内输出的部分和折叠成一个 block representation。每层的 attention 与 FFN 各有独立的 rank‑1 深度查询向量。

示意：值由固定函数生成，只表达 softmax 混合，不代表真实模型参数。

源码语义很重要：这不是给普通 residual 加一个标量 gate。_apply_attn_res 把历史块与当前部分和堆叠为 values，对其 RMSNorm 后用每层线性权重打分、沿深度 softmax，再加权原始 values。块内仍通过 prefix_sum += sublayer_output 保留清晰的累加路径。

07 · channel mixing

Stable LatentMoE：2.8T 的主体

每个 token 都走 2 个 full-width shared experts，同时只走 896 个 routed experts 中的 16 个；路由专家在半宽 latent 空间计算。

为什么叫 Stable

Normalized LatentMoE在 routed experts 聚合后、升维前加入 3584 维 RMSNorm，控制不同专家组合带来的尺度波动。
SiTU‑GLU · bounded activation[4·tanh(g/4)·σ(g)] ⊙ [25·tanh(u/25)]；两条乘法分支都有软上限。
Quantile Balancing · training onlyTop‑k 用 score + bias 选路，但混合权重只用原始 sigmoid score；训练时按目标负载分位数更新 bias，推理时冻结。

Layer 1

唯一 dense FFN：7168 → 33792 → 7168，使用相同 SiTU‑GLU。

Layers 2–93

92 个 Stable LatentMoE；routed expert 为 3584 → 3072 → 3584。

Checkpoint dtype

配置把 routed Linear 权重压成 MXFP4；attention、shared experts、dense FFN、vision、projector 与 LM head 在 ignore 清单中。

08 · native vision

MoonViT‑V2：视觉 token 的原生入口

论文强调从头训练与 next-token prediction；源码则让我们看到精确的 patch、位置编码、Vision Block 与 projector 实现。

论文层面：MoonViT‑V2 从随机初始化开始，直接接受 next-token prediction 训练；报告认为这比接入 SigLIP 初始化具有更稳定的 gradient norm，并能把细粒度文字/结构特征直接塑造成语言模型需要的表示。
代码层面：论文写的是空间/时间分解注意力；当前官方 HF 参考源码对每个媒体样本的 t·h·w tokens 做一次 packed non-causal attention，之后统一 temporal mean pooling。这里保留差异，不把论文描述硬改成源码行为。

09 · forward path

一次多模态 forward 发生了什么

这里严格按 KimiK3ForConditionalGeneration.forward 与 KimiLinearModel.forward 排序。

1 · Text embeddinginput_ids [B,T] → inputs_embeds [B,T,7168]；媒体占位符 token id 为 163605。
2 · Optional vision extractionpatchify 后的 pixel_values + grid_thws → MoonViT‑V2 → tpool/2×2 merge → PatchMergerMLPV2 → visual features [Nᵥ,7168]。
3 · Placeholder expansion每个 media placeholder 被对应数量的 visual tokens 替换；重建 attention mask、labels 与 position_ids。视觉 token 的 label 使用 ignore index。
4 · Hybrid decoder线性层使用 2D padding mask 与 KDA state；MLA 层使用 causal mask 与 KV cache。Block AttnRes 同时维护历史 block stack 与当前 prefix sum。
5 · Final depth retrieval最终 AttnRes 聚合 embedding、完成块与最后部分块，然后做 RMSNorm。
6 · Causal LM output非共享 lm_head: 7168→163840 产生 logits；训练时对 shift 后且 attention_mask 非零的位置计算 cross entropy。
位置编码不要混淆：视觉塔内部明确使用空间/时间位置 embedding 与 2D RoPE；语言主干则是 NoPE。外层仍生成 position_ids 以满足通用接口和 mask/cache 逻辑，但 MLA 没有应用 RoPE，KDA 依靠递推与 decay 获得顺序敏感性。

10 · paper/source audit

论文、配置与参考源码并不总是同一层级

“一致”表示结构和参数互相印证；“需区分”通常意味着论文描述训练/生产实现，而 HF 文件明确只是 reference implementation。

Hybrid schedule

论文：每块 3 KDA + 1 Gated MLA，末尾额外 MLA。配置列出 69 个 KDA 与 24 个 full-attention 层；源码按 1-based layer list 分派，完全一致。

一致
Block AttnRes

论文给出 block size=12、最终含 embedding 共 9 个来源。配置为 12；源码在 layer_idx % 12 == 0 时保存 prefix，并在末尾再做一次 output AttnRes。

一致
Stable LatentMoE

7168→3584 routed latent、896 选 16、2 shared、RMSNorm 再升维、SiTU‑GLU β=(4,25) 均能在配置与源码逐项定位。

一致
Quantile Balancing

论文详细描述训练时的分位数 bias 更新；公开 HF 推理代码禁止 MoE training，只读取并冻结 e_score_correction_bias 做 Top‑k。这不是缺失推理算子，而是训练算法未包含在 reference file。

需区分
MLA cache

论文强调低维 latent KV cache；HF reference source 先恢复逐 head K/V 再追加到 KimiDynamicCache。生产引擎仍可吸收 up projection 并缓存 latent，但不能从这份代码声称已经实现。

需区分
Vision attention

论文描述 intra-frame spatial / inter-frame temporal factorization；参考源码显示每个样本一次 packed non-causal attention over t·h·w，然后 temporal pooling。可能是训练实现与发布推理实现的差异。

需区分
Video input

论文与模型卡声明 image/video；视觉塔张量结构支持 t>1，但当前本地 KimiK3VisionProcessor 的 ensure_media_type 与 preprocess 只接受 image。

需区分
MTP / draft layer

论文的模型表与后训练章节包含 1 个 MTP layer，并说明它会被微调为 EAGLE‑3 draft model；发布的目标模型配置为 num_nextn_predict_layers=0，这份 HF 主干源码也没有 MTP 模块。因此总体结构图按当前发布 target model 绘制，不把独立 draft model 混入 93 层主路径。

需区分
MXFP4 / MXFP8

论文称 SFT 起进行 MXFP4 权重 / MXFP8 激活 QAT；当前 config 只编码 compressed checkpoint 的 MXFP4 权重分组与 ignore 列表，不能据此复原训练时全部 activation quantization 实现。
