01模型总览

Qwen3.5-35B-A3B 是一个原生视觉—语言、decoder-only 的稀疏混合专家模型。模型拥有约 35B 总参数，但每个 token 只激活约 3B；语言主干把 30 层线性注意力与 10 层全注意力按 3:1 周期混排，以固定大小递归状态承接大部分长程计算，再由周期性的 GQA 恢复精确内容检索。

视觉侧不是外挂式 caption encoder：图像和视频先被 27 层 ViT 编码，经 2×2 spatial merger 映射到 2048 维；这些向量直接替换序列中的视觉占位 token，和文字 embedding 一同进入同一语言主干。这就是其“原生多模态”在发布推理代码中的具体落点。

02Vision

视觉侧的任务是把不同分辨率、不同帧数的媒体变成与语言隐空间同宽的 token。它没有跨注意力 connector；对齐发生在 merger 的输出维度和后续 placeholder 替换上。CODE

2.1 动态网格与 3D Patch Embedding

预处理器用 grid_thw=(T,H,W) 描述每个样本的 patch 网格。卷积核覆盖 2 个时间片和 16×16 空间像素，因此一枚 patch 对应 3×2×16×16=1536 个标量，再投影到视觉宽度 1152。静态图像会在时间维满足相同接口；视频则保留时间网格。

pixels [N, 3, 2, 16, 16]→ flatten[N, 1536]→ Conv3D / Linear[N, 1152]

这里的 N=Σ(T·H·W) 是 batch 内所有媒体的 patch 总数。源码之后通过累积 cu_seqlens 把不同媒体打包送入非因果视觉注意力，避免把不同样本互相注意。

2.2 绝对位置插值与 Vision RoPE

Qwen3.5 在视觉塔内并行使用两类位置机制，但二者作用位置完全不同：可学习绝对位置向量加到 patch embedding，改变送入所有视觉层的 residual stream；Vision RoPE 在每个视觉注意力层内旋转 Q/K，改变 token 两两之间的注意力相位，而不旋转 V。CODE

可学习的 48×48 绝对位置表

num_position_embeddings=2304，因此初始化得到 pos_embed: Embedding(2304,1152)，并令 side=√2304=48。它可以看成一张 48×48 的可学习二维网格，每个格点存放一个 1152 维向量。实际图像的 patch 网格可以是任意 H×W；代码不是裁剪或整数取样，而是把目标网格的两条轴分别用 linspace(0,47,H/W) 对齐到完整 48×48 表的两端。CODE

h_grid[i] = i·47/(H−1),   w_grid[j] = j·47/(W−1)沿用源码变量名：目标 patch (i,j) 映射到可学习位置表中的连续坐标 (h_grid[i], w_grid[j])；常规动态网格 H,W≥2。

接下来完全沿用源码符号。h_floor=floor(h_grid)、w_floor=floor(w_grid) 是向下取整得到的上方/左侧格点；实现中写作 h_grid.int()/w_grid.int()，由于坐标非负，效果与数学上的 floor 相同。h_ceil=min(h_floor+1,47)、w_ceil=min(w_floor+1,47) 是向上相邻的下方/右侧格点。连续坐标超过 floor 的小数距离也使用代码名：

h_frac = h_grid − h_floor,   w_frac = w_grid − w_floorh_frac 表示从上方格点向下走过的比例，w_frac 表示从左侧格点向右走过的比例；二者均位于 [0,1)。

ceil 的代码语义。源码中的 h_ceil/w_ceil 表示“下一个相邻索引”，通过 floor+1 再 clamp 得到。连续坐标恰为内部整数时，它可能不同于数学函数 ceil(x)，但此时 frac=0，所有 ceil 方向的权重都是 0，插值结果仍完全一致；到 47 边界时则 clamp 为 floor=ceil=47。

pabs(i,j) = (1−h_frac)(1−w_frac)E[h_floor,w_floor] + (1−h_frac)w_frac E[h_floor,w_ceil]
+ h_frac(1−w_frac)E[h_ceil,w_floor] + h_frac·w_frac E[h_ceil,w_ceil]四个权重分别对应左上、右上、左下、右下，非负且总和为 1。

实例：8×12 网格中的 patch (3,5)

取交互演示的默认值 H=8、W=12、i=3、j=5。该 patch 在 48×48 表上的连续坐标及取整结果为：

h_grid = 3 × 47 / (8 − 1)  = 20.142857
w_grid = 5 × 47 / (12 − 1) = 21.363636

h_floor = 20    h_ceil = 21    h_frac = 0.142857
w_floor = 21    w_ceil = 22    w_frac = 0.363636
位置表角点源码中的权重表达式数值空间含义
E[20,21](1-h_frac)(1-w_frac)0.5455左上；距离最近，权重最大
E[20,22](1-h_frac)w_frac0.3117右上
E[21,21]h_frac(1-w_frac)0.0909左下
E[21,22]h_frac·w_frac0.0519右下

因此 p_abs(3,5) 是上述四个 1152 维表向量按 0.5455、0.3117、0.0909、0.0519 加权后的结果。因为 h_frac 很小，它更靠近第 20 行；因为 w_frac 约为 0.364，它在第 21 列和第 22 列之间更偏向第 21 列。

函数返回 bilinear_indices:[4,N] 和 bilinear_weights:[4,N]。模型一次查出四组位置向量，广播权重到隐藏维后求和：

# N = Σ(T·H·W), Dv = 1152
patch = patch_embed(pixel_values)                              # [N, Dv]
corners = pos_embed(bilinear_indices)                          # [4, N, Dv]
pos_abs = (corners * bilinear_weights[:, :, None]).sum(0)      # [N, Dv]
x₀ = patch + pos_abs                                           # [N, Dv]

这是一次真正的向量加法，不是 attention bias。于是第一层的 LayerNorm(x₀)、Q/K/V 投影以及后续 MLP 都能读到绝对空间位置；经 residual connection 传播后，这项讯号会留在整个 27 层视觉塔中。

为什么还要按 2×2 block 重排

绝对位置计算先在普通 raster order 上生成，再用 spatial_merge_size=2 构造的 reorder 重排为 block-major：先排列同一个 2×2 merger block 内的四个 patch，再排列下一个 block，并对每个时间片重复。Vision RoPE 的 position_ids 使用同样的 reshape–transpose–flatten 次序。因此三者——patch token、绝对位置向量和 RoPE 坐标——在进入 ViT 前保持逐项对齐。绝对位置表同样只按 H/W 查表并在 T 上重复；视觉塔内的显式时间位置要与语言侧后续 M-RoPE 的 temporal channel 区分。

raster: (0,0),(0,1),(0,2)…→ merge-aware reorderblock₀: (0,0),(0,1),(1,0),(1,1)→block₁ …

Vision RoPE：把二维坐标变成 72 维旋转相位

视觉注意力宽度为 1152、16 heads，所以 head_dim=72。模型构造 VisionRotaryEmbedding(head_dim//2=36)；其 arange(0,36,2) 产生 18 个逆频率：

ωr = 10000−2r/36,   r=0,…,17Vision RoPE 的 θ 使用该基础类默认值 10,000；它与语言模型的 rope_theta=10,000,000 不是同一个配置。

get_vision_position_ids 为每个 patch 返回二维整数坐标 (h,w)。默认 include_temporal=False，所以视频只是把同一套 H/W 坐标重复 T 次：视觉塔的 RoPE 没有显式时间轴。位置与频率外积后，先得到 18 个高度相位和 18 个宽度相位，再复制一次以匹配 72 维 head：

position_ids [N,2]×inv_freq [18]→φ [N,2,18]flatten + duplicatecos,sin [N,72]
φ = [h·ω₀…h·ω₁₇, w·ω₀…w·ω₁₇]                  # [N, 36]
angle = concat(φ, φ)                            # [N, 72]
cos, sin = angle.cos(), angle.sin()             # 每个 block 复用
q′ = q * cos + rotate_half(q) * sin
k′ = k * cos + rotate_half(k) * sin             # V 保持不变

rotate_half 把 head 前 36 维与后 36 维配对：前 18 对承载高度旋转，后 18 对承载宽度旋转。计算临时升到 float32，旋转后再还原 Q/K dtype，以降低三角函数和乘加的数值误差。相同的 cos/sin 在 27 个 block 中复用，但每层都有自己的 Q/K 投影。CODE

⟨R(φi)qi, R(φj)kj⟩ = qi⊤R(φj−φi)kj共同绝对旋转在内积中相消，留下 Δh·ω 和 Δw·ω；这就是二维相对位移进入 attention score 的位置。

两者不是重复编码。绝对位置表学习“这个 patch 位于整幅画面的哪里”的内容偏置，并通过插值适配动态分辨率；RoPE 让 Q/K 内积显式依赖二维相对位移。前者改变 token 表示本身，后者改变 token 间的匹配几何。参见 联合交互演示。

2.3 27 层 Vision Transformer

视觉注意力对每个媒体样本内部的 T·H·W patch 做完整、非因果 self-attention。27 层循环完成后，返回的 last_hidden_state 仍是 1152 维 patch 序列；真正给语言模型的是 merger 的 pooler_output。

2.4 Spatial Merger：从 patch 到视觉 token

spatial_merge_size=2 表示每个时间位置把相邻 2×2 patch 聚成一个视觉 token。四个 1152 维向量先按空间邻域拼接，再经归一化和两层投影映射到语言宽度 2048。

[T,H,W,1152]→ 2×2 shuffle[T,H/2,W/2,4608]→ MLP merger[T,H/2,W/2,2048]
Nvisual = T · H · W / 2² 每个图像或视频在语言序列中占用的视觉 token 数

没有 DeepStack。目标配置的 deepstack_visual_indexes=[]，且 Qwen3.5 VisionModel 初始化后删除了对应 merger list；因此视觉特征只在输入 embedding 层融合，不应画出向多个语言层注入视觉特征的路径。

2.5 Early Fusion：视觉向量替换占位 token

processor 先在 input_ids 中放置与视觉 token 数等量的特殊占位符。模型取得视觉特征后，用 get_placeholder_mask 检查数量与位置，再通过 masked_scatter 把对应的文字 embedding 原位替换成视觉 embedding。序列长度和因果顺序不变，模态身份由 token 类型与三维位置坐标保留。

inputs_embeds = embed_tokens(input_ids)                # [B, S, 2048]
image_embeds = visual(pixel_values).pooler_output      # [Nvis, 2048]
image_mask, _ = get_placeholder_mask(input_ids, image_features=image_embeds)
inputs_embeds = inputs_embeds.masked_scatter(image_mask, image_embeds)
outputs = language_model(inputs_embeds=inputs_embeds, position_ids=mrope_ids)

这不是把视觉特征追加到文本末尾，也不是 decoder 对 vision tower 做 cross-attention；视觉 token 从第一层起就与文字 token 处于同一 causal 序列。参见 Early Fusion 交互演示。

2.6 四路位置索引

Qwen3_5TextModel.forward 接收形状为 [4,B,S] 的位置索引：第 0 路作为普通文本位置和 causal mask 位置；后 3 路进入 Multimodal RoPE，分别承载时间、高度、宽度。纯文本时四路相同；视觉 span 内三路按网格变化。

索引通道文本 token视觉 token用途
0 · text单调递增序列位置causal mask / 通用位置
1 · temporal复制文本位置帧或时间 patch 坐标M-RoPE 时间 section
2 · height复制文本位置合并前高度坐标M-RoPE 高度 section
3 · width复制文本位置合并前宽度坐标M-RoPE 宽度 section

03Language Model

语言主干的核心不是单一 attention 变体，而是三种稀疏性的叠加：层级上只有四分之一层使用全注意力；head 级别由 16 个 query head 共享 2 个 KV head；FFN 级别每 token 只路由到 256 个专家中的 8 个。三者分别减少序列、缓存和参数激活成本。

3.1 从统一 embedding 到 logits

input ids / fused embeds [B,S,2048]→ 40 decoder layershidden [B,S,2048]→ RMSNormLM Head→logits [B,S,248320]

每层都采用 Pre-Norm，并保持残差流宽度 2048。不论 token mixer 是 DeltaNet 还是 GQA，后半段始终是同一个 Sparse MoE。Embedding 与 LM head 在权重索引中是独立参数，并未声明 tied weights。WEIGHT

3.2 40 层混合布局

配置中的 layer_types 逐层展开为十个四层组：每组前 3 层是 linear_attention，第 4 层是 full_attention。若以源码的 0-based 编号计，全注意力层为 3、7、11、15、19、23、27、31、35、39。

for group in range(10):
    layer[4g + 0] = GatedDeltaNet → SparseMoE
    layer[4g + 1] = GatedDeltaNet → SparseMoE
    layer[4g + 2] = GatedDeltaNet → SparseMoE
    layer[4g + 3] = GatedGQA      → SparseMoE

混合设计利用 GDN 的线性时间递推承担绝大多数层，同时每隔三层用完整 causal attention 重新访问显式历史。官方 Qwen3-Next 消融将其概括为：纯线性注意力长序列高效但精确 recall 较弱；纯全注意力 recall 强但代价高；3:1 混合在性能与效率之间更优。官方博客

参见 40 层时间轴演示。

3.3 Decoder Layer 的共同骨架

两条 residual 都取自归一化之前：x ← x + Mixer(Norm(x))，再执行 x ← x + MoE(Norm(x))。这种结构让更换 token mixer 不影响 FFN/残差接口。

3.4 Gated DeltaNet：可学习遗忘的矩阵记忆

对输入 x∈ℝ²⁰⁴⁸，Qwen3.5 使用分离投影生成 Q、K、V、输出门 z、写入门 β 和衰减参数 a。Q/K 有 16 个 128 维 head，V 有 32 个 128 维 head；源码把每个 Q/K head 重复两次，与 32 个 value head 对齐。

量投影后形状作用
Q, K[B,S,16,128] → repeat → [B,S,32,128]读取地址与写入地址；进入 kernel 前 L2 normalize
V, z[B,S,32,128]写入内容与 gated RMSNorm 输出门
β[B,S,32]sigmoid(b)，控制 delta 修正强度
g[B,S,32]-exp(A_log)·softplus(a+dt_bias)，取指数后成为 (0,1] 衰减
St[B,32,128,128]每层固定大小 recurrent state

Q/K/V 先经过 kernel size 4 的 depthwise causal convolution 和 SiLU，以极低成本注入最近 4 个位置的局部顺序。核心 delta rule 可按单个 head 写成：

S̃t = egt St−1
v̂t = S̃tT kt,   δt = βt(vt−v̂t)
St = S̃t + ktδtT,   ot = StTqt 先遗忘旧状态，再按当前 key 读取预测；只写入预测误差，因此称为 delta update。

若状态对当前 key 已能还原 value，则 v−v̂≈0，无需重复写入；若预测错误，外积 k δᵀ 定向修正相应地址。与把所有 K/V 留在缓存不同，状态大小不随上下文增长，但有限矩阵会产生压缩与干扰。

Prefill 与 decode

  • 多 token prefill / chunk continuation：调用 chunk gated-delta kernel；有历史缓存时先把卷积 state 拼到 chunk 左边，再只保留当前 chunk 输出。
  • 单 token decode：调用 fused recurrent kernel，原位更新卷积 state 和 recurrent state。
  • 两类缓存：每个 GDN 层保存最近 4 步的卷积上下文，以及每个 value head 的 128×128 状态矩阵。

参见 Gated DeltaNet 逐步矩阵演示。

3.5 Gated GQA：周期性的精确内容检索

全注意力层使用 16 个 query heads、2 个 KV heads 和 256 维 head。KV 共享把每 token、每层的缓存宽度从 MHA 的 2×16×256 降到 2×2×256，理论上缩小 8 倍；query 仍保留 16 个子空间。

Q,G = split(Wqgx),   K=Wkx,   V=Wvx
Y = Wo[Attention(RoPE(Q),RoPE(K),V) ⊙ σ(G)]输出门在 head 拼接后、o_proj 之前逐元素调制注意力结果。

q_proj 一次产生 query 与同形 gate，所以输出 gate 不是标量 head gate，而是每 token、每 query 通道的细粒度 sigmoid。Q/K 在 RoPE 前做 RMSNorm；RoPE 只覆盖每 head 前 64 维，即 256×0.25。剩余 192 维不旋转，兼顾位置敏感性和长距离外推。

结构Q headsKV heads每 token KV 元素/层特点
MHA 对照16168192每个 Q head 独立 K/V，缓存最大
本模型 GQA1621024每 8 个 Q heads 共享一组 K/V
MQA 对照161512缓存更小，但共享更强

参见 Gated GQA head-sharing 演示。

3.6 Partial Multimodal RoPE

配置给出 rope_theta=10,000,000、partial_rotary_factor=0.25 和 mrope_section=[11,11,10]。全注意力 head 维 256，因此实际 rotary 维度为 64，包含 32 对二维旋转；三个 section 的 11+11+10 正好分配这 32 对频率，并以 interleaved 方式应用时间、高度、宽度坐标。

θi = 10,000,000−2i/64,   R(pt,ph,pw) = Rt(11) ⊕ Rh(11) ⊕ Rw(10)上式表达 section 数量关系；具体实现交错排列，而不是简单连续拼接。

GDN 本身不使用 RoPE；M-RoPE 只在十个全注意力层提供位置相位。这使位置编码的显式计算也沿层维稀疏化。参见 三轴旋转演示。

3.7 Sparse MoE：256 选 8，再加 shared expert

每层的 router 是一个 256×2048 权重矩阵。对扁平化 token hidden state 计算 256 个 logits，float32 softmax 后取 Top-8，再把这 8 个概率重新归一化。被选中的专家是 SwiGLU MLP，单专家中间宽度仅 512。

p = softmax(Wrx),   I = TopK(p,8),   p̄i = pi / Σj∈Ipj
yrouted = Σi∈Ip̄iW2,i[SiLU(Wg,ix) ⊙ Wu,ix]shared expert 走独立 SwiGLU，并由 shared_expert_gate 调制后与 routed 输出相加。

“35B / A3B”不能简单理解为每层恰有 3B 权重参与：激活量还包括 embedding、attention/GDN、8 个 routed experts、shared expert、LM head 等全路径参数；3B 是模型卡给出的整体近似 activated parameters。训练配置另有 router_aux_loss_coef=0.001，用于鼓励负载均衡。参见 Top-k 路由演示。

3.8 稳定性设计

  • Zero-Centered RMSNorm：继承 Gemma3 风格，实际缩放为 1 + weight；权重以 0 初始化，使初始变换接近恒等。
  • QK-Norm：GQA 对 Q/K 做 RMSNorm，GDN kernel 对 Q/K 做 L2 normalize，限制相似度尺度漂移。
  • Attention output gate：官方 Qwen3-Next 博客将其与缓解 attention sink、massive activation 联系起来；源码显示 gate 确实逐元素乘在 attention 输出上。
  • GDN state 使用 float32 路径：A_log 与门控计算显式转 float，避免 fp16 下指数参数溢出。

3.9 Multi-Token Prediction

配置声明 mtp_num_hidden_layers=1，权重索引包含 mtp.pre_fc_norm_embedding、mtp.pre_fc_norm_hidden、mtp.fc、一层 full-attention + MoE 和 mtp.norm。这说明辅助模块融合当前 hidden state 与候选 token embedding，再用一个额外 decoder layer 预测更远的 token。

官方模型卡称其经过 multi-step training；Qwen3-Next 博客说明目标既是训练时增强主模型，也是在推理时产生高接受率 draft。部署示例分别使用 SGLang NEXTN 和 vLLM qwen3_next_mtp。

实现边界。HF 类的 _keys_to_ignore_on_load_unexpected=[r"^mtp.*", ...] 表明常规 Transformers 生成不会构造该旁路。checkpoint 结构能证明“权重存在”，官方部署命令能证明“专用引擎可用”，但不能据此声称当前 HF forward 已执行 MTP。

参见 MTP 验证时序演示。

3.10 长上下文：混合缓存而非零增长缓存

30 个 GDN 层的 recurrent state 与序列长度无关，但 10 个全注意力层仍保存逐 token K/V。因此总缓存仍随序列长度线性增长，只是斜率显著低于 40 层全 GQA。忽略 dtype、batch 和实现对齐后：

CKV(L)=10·L·(2·2·256),\quad CGDN=30·(32·128·128 + 4·8192)第一项随 L 线性增长；第二项为 recurrent matrix 与 Q/K/V depthwise-conv state 的近似常数元素数。

原生上下文上限为 262,144；模型卡另称可扩展至约 1,010,000。托管的 Qwen3.5-Flash 默认 1M context 还包含生产侧能力，不能与开源 checkpoint 的默认配置混为一谈。参见 缓存增长演示。

架构与训练为何相互依赖

Early Fusion 只有在预训练阶段持续看到交错的文本、图像、视频 token，才可能把统一序列接口变成真正的跨模态推理能力；MoE 的高参数容量则需要 router balance 与分布式通信设计维持有效利用；GDN 的递归训练又要求 chunked 并行 kernel 才能把理论线性复杂度转化为训练吞吐。换言之，结构图中的三个“高效模块”都对应基础设施约束。

不作反推。本文不从最终权重或 benchmark 反推数据来源、训练 token 总量、RL reward、loss mixing、蒸馏教师或安全对齐流程。官方表示更广泛任务的 scaling 结果将留待技术报告。

6.4 综合判断

  • 强项：以很低的激活参数覆盖完整 VLM、长上下文与 Agent 栈；知识、推理、文档、视频和设备操作均达到可用的高水平。
  • 代价：35B 总权重仍决定存储和显存下限；MoE 的低 FLOPs 不等于单卡易部署，专家调度与带宽仍是瓶颈。
  • 相对定位：部分 benchmark 接近 122B-A10B，部分被 dense 27B 超过；它的主要优势是能力/激活成本，而非逐项绝对最佳。
  • 慎读官方比较：家族博客给出的 397B 相对 Qwen3-Max/Qwen3-235B 的吞吐倍数不能转写为 35B-A3B 实测吞吐。
