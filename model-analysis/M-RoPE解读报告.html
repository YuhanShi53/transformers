从像素网格到旋转相位

01

先建立一张正确的地图

同一个“RoPE”名字下面有两条路径。本文聚焦语言模型全注意力层里的 M‑RoPE；视觉塔内部的二维 RoPE 是更早的一层编码。

视觉塔内部

2D

ViT patch 使用高、宽位置生成自己的旋转嵌入，帮助视觉编码器理解局部空间。它发生在视觉特征送入 LLM 之前。

统一序列内部

3D

图像/视频特征替换占位 token 后，LLM 为每个 token 准备 T/H/W 三路坐标；文本 token 的三路值相同。

真正执行旋转

25%

只有 GQA 全注意力层的 Q/K 前 64 维进入 RoPE；其余 192 维直通。线性注意力层不走这段 Q/K RoPE。

一句话心智模型

RoPE 用相位差表达相对位置；M‑RoPE 只改变“每个频率对该读取哪一条位置轴”，旋转公式本身没有变。

02

图片为何没有“吃掉”那么多位置

视觉 token 在序列维仍然逐个存在，但位置编号沿二维网格展开：一个 H′×W′ 的图像占用的最大位置跨度是 max(H′,W′)，不是 H′×W′。

位置构造规则

text: T=H=W=p   |   image: (start+t, start+h, start+w)

静态图片的 T 网格为 1，所以所有图像 token 的 T 相同；H、W 则保留二维邻接。代码在图像结束后执行 current_pos += max(grid_h, grid_w) / merge，让后续文本接在三个轴的最大值之后。

rope_delta 的作用

delta = max(position_ids)+1−input_length。二维网格把大量视觉 token 压进较短的位置跨度，因此 delta 常为负；增量生成时用它把普通序列计数校正到 M‑RoPE 坐标末端。

03

32 个频率对，如何分给三条轴

9B 每头 256 维，但 partial_rotary_factor=0.25，所以 rotary_dim=64，即 32 个二维旋转对。实现不是连续切成 TTT…HHH…WWW，而是交错成 THWTHW…TH。

越靠后的频率对，inv_freq = θ−2i/64 越小，转动越慢，承载更长尺度的位置关系。交错布局让 T/H/W 都能覆盖高、中、低频，而不是某一轴被固定在单一频段。

一个关键细节：源码先把结果初始化为全部读取 T，然后把索引 1,4,…,31 替换为 H，把 2,5,…,29 替换为 W。因此实际顺序恰好是 [T,H,W] × 10 + [T,H]。mrope_section=[11,11,10] 描述的是每轴数量。
04

M 只改相位来源，RoPE 公式照旧

每一对 Q/K 分量仍做标准二维旋转。注意 Transformers 此实现将 64 维分成前后两半配对，rotate_half([x₁,x₂])=[−x₂,x₁]；“频率对”是概念配对，不是内存中相邻的两个标量。

第 i 对的计算

ωᵢ = θ−2i/64
φᵢ = paxis(i) · ωᵢ
q′ = q·cos φᵢ + rotate_half(q)·sin φᵢ

为什么相对位置仍成立

同轴两个 token 的内积依赖相位差 (p₁−p₂)ωᵢ。图像中同行 token 的 H 相位相同、同列 token 的 W 相位相同；文本三轴相等，退化回普通 1D RoPE。

Partial RoPE

64 + 192

Q/K 的前 64 维旋转，后 192 维保持原值。既注入显式位置，也保留大部分无旋转通道。

作用层数

8 / 32

9B 配置每 4 层一个 full attention，共 8 层 GQA 使用这段 M‑RoPE；其余 24 层是 Gated DeltaNet。

频率底数

10⁷

更大的 rope_theta 让低频转得更慢。模型声明最大位置长度 262,144，但支持长度不只由这一参数单独决定。

把数学逐行对回源码

以下为核心逻辑的等价摘录；链接指向本地 Transformers 实现。Qwen3.5 存在 modular 源文件，正式修改应改 modular_qwen3_5.py，而不是生成的 modeling 文件。

① 生成视觉三轴坐标 · get_vision_position_ids
H′ = grid_h // spatial_merge_size
W′ = grid_w // spatial_merge_size

t = arange(T′) * time_interval
h = arange(H′) + start_position
w = arange(W′) + start_position

T, H, W = meshgrid(t, h, w)
positions = stack([T, H, W]).reshape(3, -1)
positions[0] += start_position
② 拼接文本 / 视觉段 · get_rope_index
if modality == TEXT:
    pos = arange(text_len).expand(3, -1) + current
    current += text_len
else:
    pos = get_vision_position_ids(current, grid)
    current += max(grid_h, grid_w) // merge

delta = positions.max() + 1 - input_length
③ 三轴频率矩阵与交错
freqs = inv_freq[..., None] @ position_ids[..., None, :]
freqs_t = freqs[0]              # 初始全 T

for dim, offset in [(1,1), (2,2)]:
    length = mrope_section[dim] * 3
    idx = slice(offset, length, 3)
    freqs_t[..., idx] = freqs[dim, ..., idx]

emb = cat((freqs_t, freqs_t), dim=-1)
④ 只旋转 Q/K 前 rotary_dim
rotary_dim = cos.shape[-1]  # 64
q_rot, q_pass = q[..., :rotary_dim], q[..., rotary_dim:]
k_rot, k_pass = k[..., :rotary_dim], k[..., rotary_dim:]

q_rot = q_rot * cos + rotate_half(q_rot) * sin
k_rot = k_rot * cos + rotate_half(k_rot) * sin
q = cat([q_rot, q_pass], dim=-1)
k = cat([k_rot, k_pass], dim=-1)
四路输入的边界：生成准备阶段可以把 position_ids 拼成 [4,B,S]：第 0 路供线性注意力使用，后 3 路才是全注意力 M‑RoPE 的 T/H/W；普通多模态 forward 也可能只传后三路。进入 Qwen3_5TextRotaryEmbedding 的始终是三路。因此“三轴 M‑RoPE”和代码中偶尔出现的“四路 position ids”并不矛盾。

序列长度、图片大小与生成阶段

三个量要分开：token 数决定注意力/缓存规模；位置最大值决定 RoPE 相位范围；像素尺寸先决定视觉网格，再间接改变前两者。

变化视觉 token 数位置跨度直接后果
宽高同时 ×2约 ×4约 ×2序列计算增长快于最大 M‑RoPE 坐标
只加图前文本不变整体起点后移图像三个轴都加同一 start_position
长宽比增大取决于面积由更长边主导max(H′,W′) 决定图像后的 current_pos
纯文本输入0等于文本长度T=H=W，严格退化为 1D RoPE
继续生成每步 +1每步 +1三轴重新同步，用缓存的 rope_delta 校准起点
视频输入T′H′W′T 轴按帧/时间推进Qwen3.5 用时间戳分隔视频片段，并把 video grid 拆开处理

不要把跨度当 token 数

例如 8×12 的 LLM 图像网格有 96 个 token，却只把位置游标推进 12。两者分别服务于计算量与几何坐标。

不要把 M‑RoPE 当 resize

resize、patchify、merge 决定网格；M‑RoPE 接收既成的 grid_thw 并编号，本身不改变图像或 token 数。

不要把 theta 当长度开关

theta=10⁷ 规定频率谱。可用上下文还取决于训练、配置、缓存与推理框架。
